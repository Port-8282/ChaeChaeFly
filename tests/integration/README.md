# 통합 테스트 위치

서비스 내부 단위 테스트는 각 서비스의 `tests/`에 둔다. 여기는 서비스 여러 개를 연결하는 검증 코드와 작은 테스트 fixture를 위한 위치다. 현재 실행 테스트는 아직 없다.

초기 통합 검증 6개:

1. 정상 이벤트: JSON 전송 → 상태 갱신 → 계산 → 비용·후보 표시 → 선택·사유·보고서 연결.
2. 이벤트 중복·순서 역전: 같은 이벤트를 재전송해도 중복 반영되지 않고, 오래된 결과가 최신 추천을 덮어쓰지 않음.
3. 불가능한 입력·스케줄: 제약 위반이나 입력 오류를 표시하고 유효한 후보·비용인 것처럼 출력하지 않음.
4. ML 갱신·오류: 기존 결과 조회 유지, 준비 전 예측 차단, 제한 재시도, 한 계산 안에서 모델 버전 혼용 방지.
5. 재시작·배포 실패: 작업 기록 복구, 중복 실행 방지, 직전 성공 앱 버전으로 복구 후 다시 검증.
6. DB 보관·복원: 컨테이너 교체 후 데이터 유지, 별도 DB에 백업 복원, 선택 스냅샷·사유·보고서 일치 확인.

이는 인프라·통합 검증 초안이며 공식 요구사항 테스트와 아직 매핑하지 않았다. 최종 요구사항의 Must는 모두 테스트에 연결한다. Mock API 연결 성공과 실제 최적화 로직의 검증 성공은 구분해서 기록한다.
